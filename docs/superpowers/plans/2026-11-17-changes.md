# Changes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A task's pane gets a `Thread | Changes n` switch; Changes shows the task's jj changes per project since its start, each as diffs whose hidden lines load on demand; and a thread Edit/Write diff on a large file (no `originalFile`) opens its bars from the file as it is now in the task's workspace, when the edit still matches it.

**Architecture:** A server module (`src/tasks/changes.ts`) lists a task's changes from the project's replica (`--ignore-working-copy`, so mid-turn work shows as of the last snapshot, refreshed on the same triggers as the task's bookmarks), gives a change's (or the whole range's) `jj diff --git`, a file's lines at a revision, and a file's lines on disk in the task's workspace. `TaskObject` serves them. The shared diff view learns to load the file on the first bar click (`load`), to read it as the new side and check it fits (`side: "new"`), to start closed, and to show binary files; the parser unquotes git-quoted paths.

**Tech Stack:** TypeScript, Bun (`bun test`), jj 0.45, chord objects, Preact.

**Spec:** `docs/superpowers/specs/2026-11-16-diffs-memory-review-design.md` (piece 3 "Changes", incl. `workspaceFile`; "The shared diff view"; "Copy").

## Global Constraints

- Labels exactly: `Thread`, `Changes`, `All changes`, `Working copy`, `empty`, `Expand`, `binary`; gap bars `↑ n lines`, `↕ n lines`, `↓ n lines`, and `↓ lines` when the count is not known yet. Summary line `n changes on <start>`. No helper sentences.
- A task's work in a project is `<base>..<line>`: `base` the manifest's per-project commits (`src/tasks/manifest.ts:15`), joined with `|`; `line` the bookmark `meddle/task/<taskId>/<project name>` in the project's replica. Newest first; the first is the working copy.
- Nothing in the dashboard fetches a file until a bar or `Expand` is clicked.
- A thread diff without `originalFile` opens its bars from the workspace file only if every `+` and context line of its hunks equals the file at its new line number; otherwise the bars go plain.
- Server reads use `--ignore-working-copy` and never write; `workspaceFile` reads only regular files under the task's workspace (real paths), at most 2 MiB, else refuses.
- Moved or archived tasks: the calls refuse (`unavailable: moved` / `archived`); the view says `Changes` is unavailable by hiding the switch.
- jj, not git: `jj commit -m`. No attribution trailers. Only the tests each step names; never the full suite.

## Review Focus

- A task started on another task's change (base not on the default branch): only its own changes are listed. → Task 2, `taskChanges lists only the task's own work`.
- A task whose project has no default branch: still lists its changes. → Task 2, same test with no default branch configured.
- A path with spaces or non-ASCII in `jj diff --git` (git quotes it): parsed to the real path. → Task 1, `parseGitDiff unquotes git-quoted paths`.
- A thread edit followed by another edit to the same region: the workspace file no longer fits, so bars stay plain rather than showing wrong lines. → Task 1, `fitsNewSide refuses a file that moved on`.
- `workspaceFile` given a path outside the workspace, through `..` or a symlink: refused. → Task 2, `workspaceFile stays inside the workspace`.

### Task 1: The diff view loads on demand, reads the new side, starts closed

**Files:**
- Modify: `src/dashboard/ui/diff-model.ts`, `src/dashboard/ui/diff.tsx`, `src/dashboard/ui/git-diff.ts`, `src/dashboard/ui/index.html`
- Test: `test/diff-model.test.ts`, `test/git-diff.test.ts`

**Interfaces:**
- `DiffRow`'s gap gains `count: number | null` (null: not known yet). `gapLabel` gives `↓ lines` for a null count.
- `diffRows(hunks, file, opened = new Map(), opts: { side?: "old" | "new"; loadable?: boolean } = {})`:
  - `side: "new"` reads revealed lines from a file that is the new side: old line `o` is `file[o + offset - 1]`; a gap can open when the file reaches `to + offset`; the below gap ends at `file.length - lastOffset`.
  - `loadable: true` with `file === null`: gaps above and between are `canOpen: true` with their counts; a below gap `{ where: "below", key: <its first old line>, count: null, canOpen: true }` is added. `opened` is ignored until there is a file.
- `export function fitsNewSide(hunks: readonly Hunk[], file: readonly string[]): boolean` — every `+` and context line (`\` lines skipped) equals `file[newLine - 1]`.
- `DiffView` props become `{ hunks; file: readonly string[] | null; load?: () => Promise<readonly string[] | null>; side?: "old" | "new"; head?; closed?: boolean }`. A click on a bar (or `Expand`) with no file calls `load()` once (concurrent clicks share it); with `side: "new"` a loaded file that fails `fitsNewSide` is dropped and the bars go plain; a null or failed load also leaves plain bars. Then the click's open applies. `closed: true` starts with only the head shown; clicking the head's path toggles the body.
- `FilePatch.binary: true` draws the head with a `binary` tag and no body.
- `parseGitDiff` unquotes git's C-style quoted paths (`"a/na\303\257ve.md"` → `naïve.md`, `\t`, `\"`, `\\`, octal bytes as UTF-8).

### Task 2: A task's changes, on the server

**Files:**
- Create: `src/tasks/changes.ts`
- Test: `test/changes.test.ts`

**Interfaces:**
- `export type TaskChange = { change: string; commit: string; description: string; files: number; added: number; removed: number; empty: boolean; conflicted: boolean; workingCopy: boolean }`
- `export type ProjectChanges = { project: string; name: string; start: string; changes: TaskChange[] }` — `start` is a local bookmark on a base commit when there is one (prefer the project's default branch), else the base's short change id (8).
- `export async function taskChanges(cfg: NodeConfig, p: ManifestProject, taskId: string): Promise<ProjectChanges>` — `<base>..<line>` (Global Constraints), newest first, `workingCopy` true for the line's own commit (the bookmark sits on the workspace's working-copy change). A missing line bookmark → `changes: []`.
- `export async function changeDiff(cfg, p: ManifestProject, taskId: string, change: string | "all"): Promise<string>` — `jj diff --git -r <change>`; for `"all"`, `--from <base> --to <line>` (several base commits: `--from` their merge base is not well defined, so use the first base commit and say so in the doc comment).
- `export async function changeFile(cfg, p: ManifestProject, rev: string, path: string): Promise<string | null>` — `jj file show -r <rev> root-file:"<path>"`; `rev` is a change id, a change id with one trailing `-`, or a commit id from `p.base`; null when absent.
- `export async function workspaceFile(p: ManifestProject[], path: string): Promise<string | null>` — `path` absolute; must resolve (realpath) inside one of the projects' workspace realpaths; regular file only; at most 2 MiB; null when absent; throws `outside` / `too-large` / `not-a-file` errors otherwise.
- All jj calls: `--ignore-working-copy`. Ids validated (`/^[0-9a-z]+-?$/` or a 40-hex commit id) before use; paths passed as `root-file:` filesets via the shared builder in `src/projects/memory-names.ts`.

- [ ] **Step 1: Failing tests** in `test/changes.test.ts`, on a real jj repo with a workspace made like `src/tasks/provision.ts` does (follow `test/helpers.ts` / existing provision tests for setup; a minimal repo with `main`, a task workspace, and the task bookmark set on its working-copy change is enough):
  - `taskChanges lists only the task's own work`: base = a commit on another line (not `main`); two committed changes plus a non-empty working copy → three changes, newest first, the first `workingCopy: true`, counts from `self.diff().stat()`; the other line's commits are absent. Repeat with no default branch: same result, `start` the base's short id.
  - `changeDiff gives one change or the whole range`, `changeFile reads a revision and the parent form`.
  - `workspaceFile stays inside the workspace`: a file inside → its text; `<ws>/../x` → `outside`; a symlink in the workspace pointing outside → `outside`; a directory → `not-a-file`; a 3 MiB file → `too-large`.
