# Task bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign a task page's bottom bar: each project with its line's change id (click to copy), tokens, then the
node pill beside the model pill on the right.

**Architecture:** A pure function turns the manifest's projects and the task's bookmarks into one entry per project;
`BottomBar` in `src/dashboard/ui/Task.tsx` renders them inline, or collapsed into a pill with a popover (three or more
projects, or phone width via CSS).

**Tech Stack:** Preact, Bun test, iconoir icons, plain CSS in `src/dashboard/ui/index.html`.

**Spec:** `docs/superpowers/specs/2026-11-16-task-bar-design.md`

## Global Constraints

- Dark mode first; colours only from the existing tokens (`--fg`, `--fg-soft`, `--muted`, `--warn`, `--line-strong`, …).
- Labels terse: one word where the icon or position says the rest (`conflicted`, `Projects`).
- Change ids shown as their first 8 characters, monospace; the copy puts the full change id on the clipboard.
- No "+" / Add project control in this change.
- Use jj for commits (`jj describe` / `jj new`), no AI attribution.

## Review Focus

- A task with no project: `◉ no project`, no revision, nothing to copy.
- A project whose own bookmark is missing (just provisioned, or only side lines like `.before-1`): name alone.
- A conflicted line (`changeId` ""): `conflicted` in `--warn`, not a button.
- Clipboard API missing (dashboard reached over plain http on another host, not a secure context): the copy still
  works through a fallback, or at least fails without throwing.
- Phone width with one project: the inline entry hides and the collapsed pill shows; nothing scrolls sideways.

### Task 1: One entry per project

**Files:**
- Modify: `src/dashboard/ui/sidebar-model.ts` (beside `usageShort`)
- Test: `test/ui.test.ts`

**Interfaces:**
- Produces: `export type ProjectLine = { name: string; workspace: string; changeId: string | null; conflicted: boolean }`
  and `export function projectLines(taskId: string, projects: readonly { name: string; workspace: string }[], bookmarks: readonly { name: string; changeId: string }[]): ProjectLine[]`

- [ ] **Step 1: Write the failing test** `test("projectLines: each project with its own line's change id, in manifest order", …)`

```ts
const t = "t1";
const bm = [
  { name: "meddle/task/t1/swarm", changeId: "tplnrwsvqkxm0000" },
  { name: "meddle/task/t1/meddle.before-1", changeId: "zzzzzzzz" },
  { name: "meddle/task/t1/meddle", changeId: "kqxyzmwnrstl0000" },
  { name: "meddle/task/t1/broken", changeId: "" },
];
expect(projectLines(t, [{ name: "meddle", workspace: "meddle" }, { name: "swarm", workspace: "swarm" }], bm)).toEqual([
  { name: "meddle", workspace: "meddle", changeId: "kqxyzmwnrstl0000", conflicted: false },
  { name: "swarm", workspace: "swarm", changeId: "tplnrwsvqkxm0000", conflicted: false },
]);
expect(projectLines(t, [{ name: "broken", workspace: "broken" }], bm)).toEqual([{ name: "broken", workspace: "broken", changeId: null, conflicted: true }]);
expect(projectLines(t, [{ name: "fresh", workspace: "fresh" }], bm)).toEqual([{ name: "fresh", workspace: "fresh", changeId: null, conflicted: false }]);
expect(projectLines(t, [], bm)).toEqual([]);
```

### Task 2: The bar

**Files:**
- Modify: `src/dashboard/ui/Task.tsx` (`BottomBar`, drop `bookmarkText`)
- Modify: `src/dashboard/ui/common.tsx` (add `copyText`)
- Modify: `src/dashboard/ui/icons.tsx` (add `copy`, `check` from `iconoir/icons/copy.svg`, `iconoir/icons/check.svg`)
- Modify: `src/dashboard/ui/index.html` (bar CSS, phone media query)
- Test: `test/ui.test.ts` ("the dashboard bundle builds" covers the imports), `bun run typecheck`

**Interfaces:**
- Consumes: `projectLines`, `ProjectLine` (Task 1).
- Produces: `export async function copyText(text: string): Promise<boolean>` in `common.tsx`:
  `navigator.clipboard.writeText` when present, else a hidden textarea and `document.execCommand("copy")`; false on
  failure, never throws.

- [ ] **Step 1: Render the bar**, left to right:
  - projects: `projects.length === 0` → `<span class="bar-item bar-project">◉ no project</span>`. Otherwise a
    `ProjectEntry` per line (`◉ name`, then the revision: a `button.rev` with the id's first 8 chars and the copy icon,
    `title` = full id; after a successful copy the icon is `check` for 1.5 s; conflicted → `span.rev.flag` with
    `conflicted`; no line → nothing). Entry `title` = `name (workspace)`.
  - inline list wrapped in `.bar-projects`; with 3+ projects it is not rendered and only the collapsed pill is.
  - collapsed pill: `button.pill.bar-collapsed` `◉ {first} +{n-1} ▾` (`+N` only when n > 1) opening a `Popover`
    (`above: true`, `wide`) with `menu-head` "Projects" and one row per project: name left, revision (same
    `ProjectEntry` revision control) right. Rendered always when there is at least one project; CSS shows it only when
    `.bar-projects` is absent or hidden.
  - `.bar-sep` (1 px × 14 px, `--line-strong`), then the tokens `bar-item` as today.
  - `.bar-gap`, then the node: archived → `⌂ archived on …` text; else the Move pill as today; then `<Settings>`.
- [ ] **Step 2: CSS** in `index.html`: `.bar-projects { display: flex; gap: 14px; min-width: 0 }`; `.rev` monospace
  12px `--fg-soft`, no border/background, `padding: 0 4px`, hover `--hover`; `.rev .ico` `--muted`;
  `.bar-collapsed` hidden unless it is the only project control (`.bar-projects + .bar-collapsed { display: none }`).
  Phone (`max-width: 760px`): `.bar-projects`, `.bar-sep` hidden, `.bar-collapsed` shown; replace the old
  `.bar > .bar-item:not(.bar-project)` rule so tokens stay hidden; drop the now-unused `.bar-project` max-width if
  nothing uses it.
- [ ] **Step 3: Verify** `bun test test/ui.test.ts && bun run typecheck` — expect all pass, no type errors.
