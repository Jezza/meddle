# Graph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Project page shows every online node's branches and task lines as one commit graph, in place of the Copies table; the Branches section stays only for conflicted or fetching branches.

**Architecture:** Each node's `ProjectObject` serves state `graph`: the commits of its replica from the default branch's parent up to every counted bookmark (branches, the project's task lines not archived), read by one `jj log` that is skipped when the bookmarks have not moved. It replaces state `heads`, whose only reader was the Copies table. The dashboard merges every online holder's `graph` by commit id, labels each bookmark with the nodes that have it there (`behind`, `not pushed`), lays the lanes out with a pure function, and draws one SVG per row as mockup board 2. `Older` asks the home for `::<counted bookmarks>` with a larger limit.

**Tech Stack:** TypeScript, Bun (`bun test`), jj 0.45, chord objects, Preact.

**Spec:** `docs/superpowers/specs/2026-11-16-diffs-memory-review-design.md` (piece 4 "Graph"; "Copy").

## Global Constraints

- Labels exactly: `Graph`, `Older`, `⌂ <node> · <node>`, `· n behind`, `· not pushed`, `context failed to load`. No helper sentences.
- A task line is `meddle/task/<id>/<project name>` (local, on its holder) or `task/<id>/<project name>@meddle` (remote, elsewhere); both are reported as `{ kind: "task", task: <id> }`. Anything else under `meddle/` (side lines `.before-<n>`, `meddle/conflict/…`), `base/…@meddle`, `@git` and every other remote bookmark is left out. Lines whose row is archived are left out. Branches are local bookmarks, by name.
- At most 200 commits per read (`GRAPH_MAX`), newest first. With a default branch: `::B ~ ::(<default>--)` (B the counted bookmarks' commits); without one: `::B`.
- Server reads use `--ignore-working-copy` and never write.
- jj, not git: `jj commit -m`. No attribution trailers. Only the tests each step names; never the full suite.

## Review Focus

- A node whose replica is the user's checkout with local bookmarks of its own (`spike`): drawn, `not pushed`, coloured `--warn`. → Task 3, `a commit only one node has is not pushed`.
- One node's `main` an ancestor of another's: one pill where most nodes have it, a dashed `behind` pill at the older commit with `· 1 behind`. → Task 3, `a bookmark behind elsewhere is labelled behind`.
- A new commit on a task line (rows added at the top) leaves the lanes of every row below unchanged; the default branch stays in lane 0. → Task 3, `lanes are stable as rows are added at the top`.
- A parent outside the read (cut at 200, or below `<default>--`): a short dashed stub under the commit, and `Older` shows. → Task 3, `a parent outside the graph ends in a stub`.
- A conflicted local branch (several targets): each target drawn with the branch's pill; it is also listed under Branches. → Task 1, `projectGraph labels every target of a conflicted bookmark`.

**Interfaces:**
- Produces:
  - `export type GraphBookmark = { kind: "branch"; name: string } | { kind: "task"; task: string }`
  - `export type GraphCommit = { commit: string; change: string; parents: string[]; description: string; immutable: boolean; time: number; bookmarks: GraphBookmark[] }` — `description` its first line; `time` the committer timestamp in ms; `parents` commit ids (all of them, in or out of the read).

  - `export async function projectGraph(cfg: NodeConfig, replica: string, probe: GraphProbe, defaultBranch: string | null, limit = GRAPH_MAX): Promise<GraphCommit[]>` — one `jj --ignore-working-copy log --no-graph --limit <limit>` over the revset in Global Constraints (B = the probe's commits; empty B → `[]` without a call), template `commit_id`, `change_id`, `parents.map(|c| c.commit_id()).join(",")`, `immutable`, `committer.timestamp()` (parse to ms), `description.first_line()` last, `\x1f`-separated; each commit's `bookmarks` from the probe. `<default>` is the default branch's local bookmark commit(s) from the probe; absent → as without one.
  - `export async function olderGraph(cfg, replica, probe, limit): Promise<GraphCommit[]>` — `::B`, no lower bound, at most `limit`.

### Task 3: Merging the nodes' graphs and laying out lanes

**Files:**
- Create: `src/dashboard/ui/graph-model.ts` (pure: no Preact, no DOM)
- Test: `test/graph-model.test.ts`

**Interfaces:**
- Consumes: `GraphCommit`, `GraphBookmark` (Task 1).
- Produces:
  - `export type NodeGraph = { nodeId: string; graph: readonly GraphCommit[] }`
  - `export type Label = { bookmark: GraphBookmark; nodes: string[]; behind: number | null; notPushed: boolean }` — `nodes` the node ids with the bookmark at this commit, in the input order; `behind` the count of commits between here and the bookmark's furthest position, for a position that is an ancestor of another node's; `notPushed` when this commit is in exactly one node's graph and more than one node graph was given.
  - `export type Row = { commit: GraphCommit; labels: Label[] }`
  - `export function mergeGraphs(nodes: readonly NodeGraph[]): Row[]` — union by commit id, ordered children before parents, among ready commits newest `time` first, then commit id. `behind`: the commits that are ancestors-or-self of the furthest position and not ancestors-or-self of this one, within the merged graph. Two positions neither ancestor of the other: both plain.
  - `export type Seg = { kind: "through" | "up" | "down" | "in" | "out" | "stub"; lane: number }` — `through` a lane passing the row top to bottom; `up` top to the node (its own lane); `down` node to bottom (its own lane); `in` a lane from the top curving into the node (a child on another lane); `out` from the node curving to a lane's bottom (a second parent on another lane); `stub` a dashed short line under the node to a parent outside the graph.
  - `export type Laid = { lane: number; segs: Seg[] }`
  - `export function layoutLanes(rows: readonly Row[], defaultBranch: string | null): { rows: Laid[]; lanes: number }` — `lanes` the most used in any row.
  - `export function hasOlder(rows: readonly Row[]): boolean` — some parent is not in `rows`.
- Lane rule (stable as rows are added at the top): the default branch's first-parent chain (from its furthest position) is lane 0. Every other commit continues its first parent's lane when it is that parent's first child to do so (the newest child continues; the others start chains). Chains are given lanes oldest chain bottom first, each the leftmost lane free over its rows; a chain whose top commit has no child in the graph (a head) holds its lane up to the top row, so a new commit on it never collides.
