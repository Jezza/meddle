# Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Project page shows the project's memory entries, lets you edit, add and delete them on the project's home, and shows the memory's history with diffs, naming the task behind each change.

**Architecture:** Reads come from the memory repo on the node the dashboard asks (the home, else any holder, read-only), through new `ProjectObject` methods backed by a read module (`src/projects/memory-view.ts`). Writes go through `memory-sync.ts` under the turn syncs' lock and the push lock, committing only the edited path. Turn-end commits gain the task id. A `memoryChanges` event (fired by syncs, writes and peer pushes) refreshes `ProjectObject.memoryHead`, which the dashboard watches. The shared diff view gets a head with `Expand`, a git-diff parser, and keeps the change in place when a `↑` bar opens.

**Tech Stack:** TypeScript, Bun (`bun test`), jj 0.45 (colocated repos), chord objects (`src/state/contracts.ts`, `src/state/host.ts`), Preact.

**Spec:** `docs/superpowers/specs/2026-11-16-diffs-memory-review-design.md` (piece 2 "Memory", "The shared diff view", "Copy").

## Global Constraints

- Labels exactly: `Memory`, `New`, `Edit`, `History`, `Delete`, `Save`, `Cancel`, `Index`, `Dashboard`, `Imported`, `offline`, `Changed`, `Busy`, `Expand`. No helper sentences anywhere in the UI.
- Writes happen on the project's home only. Under both `serialised("memory-sync\0" + repo)` (the key `memory-sync.ts` uses) and `serialised(repoKey(repo))` (`src/serial.ts`, the key a peer's push takes in `src/git/serve.ts`), taken in that order.
- A write commits only its path: `jj commit -m "memory: dashboard" <path>`.
- Turn-end commit message: `memory from <shortId(node)>: task <taskId>` (unchanged `memory from <shortId(node)>` when no task id is given).
- Entry paths: a flat file name matching `^[A-Za-z0-9][A-Za-z0-9._-]*\.md$`; anything else is refused.
- `base` is the sha256 hex of the file's bytes on disk when it was opened, or null for a new file.
- Reads never snapshot the memory repo's working copy: jj reads use `--ignore-working-copy`; file contents come from disk.
- jj, not git: `jj commit -m`. No attribution trailers. Run only the tests each step names; never the full suite.

## Review Focus

- An agent writes an entry while you edit it: Save refuses with `Changed` and the box keeps your text. → Task 3, `writeMemory refuses when the file changed since it was opened`.
- A turn of a task of the project is running on the home and a peer has pushed memory meanwhile: Save refuses with `Busy` and moves nothing under the agent. → Task 3, `writeMemory refuses while live when the working copy is behind memory`.
- An agent left another file uncommitted when you save: that file stays uncommitted in `@`, only yours is committed. → Task 3, `writeMemory commits only its own path`.
- A file name with `..`, a slash, or not ending `.md`: refused before touching disk. → Task 3, `memory paths are confined`.
- The home is offline: Memory still shows a holder's entries and history, read-only, marked `offline`. → Task 5, `memorySource picks the home, else a holder, read-only`.

**Interfaces:**
- Consumes: `Hunk`, `diffRows`, `DiffRow`, `Opened`, `nextOpen` from `diff-model.ts`.
- Produces:
  - `export type FilePatch = { path: string; oldPath?: string; status: "modified" | "added" | "deleted" | "renamed"; binary: boolean; hunks: Hunk[]; added: number; removed: number }`
  - `export function parseGitDiff(text: string): FilePatch[]` — parses `jj diff --git` output. A hunk header with a count of 0 has its start read as start + 1 (git writes the line before; `diff-model` wants the first line of the range), so `@@ -0,0 +1,1 @@` gives `oldStart: 1, oldLines: 0`. `\ No newline at end of file` lines stay in `lines` (diffRows skips them) and are not counted.
  - `DiffView` gains optional props `head?: { path: string; status: FilePatch["status"]; added: number; removed: number }` and keeps `{ hunks, file }`. With `head`, it draws `<div class="diff-head">` above the rows: the path (monospace), a `new` / `deleted` / `renamed` tag when not modified, `+n −n`, and an `Expand` button that sets every current gap's key to `"all"`; `Expand` is shown only when some gap can open.
  - Opening a gap whose `where` is `"above"` keeps the first hunk where it was on screen: before the update, note the `offsetTop` of the first row after that gap; after it (`useLayoutEffect`), add the difference to the `.diff` box's `scrollTop`.

### Task 2: Reading memory

**Files:**
- Create: `src/projects/memory-view.ts`
- Test: `test/memory-view.test.ts`

**Interfaces:**
- Produces (all take `cfg: NodeConfig, repo: string`, the memory repo's path; jj calls use `--ignore-working-copy`):
  - `export type MemoryEntry = { path: string; size: number; hash: string; name: string | null; description: string | null; type: string | null; last: MemoryChange | null }` — `hash` is sha256 hex of the bytes on disk; `name` / `description` from frontmatter; `type` from `metadata.type`, else a top-level `type:`; `last` the newest change under `memory` touching the path (null when the file is not in it yet).
  - `export type MemoryChange = { change: string; at: string; node: string | null; task: string | null; kind: "task" | "dashboard" | "import" | "node" | "other"; description: string; files: string[]; added: number; removed: number }` — from the description: `memory from <node>: task <id>` → task; `memory from <node>` → node; `memory: dashboard` → dashboard; `import memory from …` → import; anything else → other. `at` is the author timestamp, ISO.
  - `export async function memoryEntries(cfg, repo): Promise<MemoryEntry[]>` — every `*.md` file in the repo's top folder on disk, `MEMORY.md` first, then by `name ?? path`.
  - `export async function memoryFile(cfg, repo, path: string, change?: string): Promise<string | null>` — the file on disk, or at `change` (`jj file show -r <change>`); null when absent.
  - `export async function memoryHistory(cfg, repo, opts: { before?: string; limit: number; path?: string }): Promise<MemoryChange[]>` — `::memory ~ root()` newest first (only changes touching `path` when given), starting below `before` when given.
  - `export async function memoryDiff(cfg, repo, change: string): Promise<string>` — `jj diff --git -r <change>`.
  - `export function parseFrontmatter(text: string): { name: string | null; description: string | null; type: string | null }` — the `---` block at the top only; values may be quoted; nested `metadata:` keys indented.
- Template that gives a change's fields in one call (checked on jj 0.45): `change_id ++ "\t" ++ author.timestamp() ++ "\t" ++ description.first_line() ++ "\t" ++ self.diff().stat().total_added() ++ "\t" ++ self.diff().stat().total_removed() ++ "\t" ++ self.diff().files().map(|f| f.path()).join(",") ++ "\n"`.

- [ ] **Step 1: Write the failing tests** in `test/memory-view.test.ts`, on a real jj repo made in a temp dir (`initColocated` from `src/jj.ts` and the jj identity setup the other jj tests use; see `test/helpers.ts`), with a `memory` bookmark set the way `importMemory` sets it:
  - `parseFrontmatter reads name, description and metadata.type`: for `"---\nname: terse-ui-labels\ndescription: \"one word\"\nmetadata:\n  type: feedback\n---\nbody"` → `{ name: "terse-ui-labels", description: "one word", type: "feedback" }`; no frontmatter → all null; a top-level `type: project` → `type: "project"`.
  - `memoryEntries lists MEMORY.md first and reads what is on disk`: commit `MEMORY.md` and `b.md` with message `memory from abc123: task t1`, then write an uncommitted `a.md`; entries are `MEMORY.md`, `a.md`, `b.md` (by name); `a.md.last` is null; `b.md.last` is `{ kind: "task", node: "abc123", task: "t1" }`; `hash` equals sha256 of the bytes; a `notes.txt` and a sub-folder are not listed.
  - `memoryHistory names who changed memory`: four commits under `memory` with the four description shapes give kinds `task`, `node`, `dashboard`, `import` newest first, each with `files`, `added`, `removed`; `{ limit: 2 }` gives two; `{ before: <second's change>, limit: 10 }` gives the ones below it; `{ path: "b.md" }` only those touching `b.md`.
  - `memoryFile and memoryDiff read a change`: `memoryFile(…, "b.md", <first change>)` is that version's text; an absent path is null; `memoryDiff` of a change contains `diff --git a/b.md b/b.md`.
  - `reads leave the working copy alone`: after the reads, `jj --ignore-working-copy log -r @` shows the same commit as before them (no snapshot), with `a.md` still uncommitted.
